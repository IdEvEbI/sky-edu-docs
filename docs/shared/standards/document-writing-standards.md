# 文档编写规范（数科汇智平台）

> 目标：保证文档“能用、好找、可维护”。本规范强调单一原则、务实表达，复杂主题可采用总分总结构。

## 1. 基本原则

- **单一原则（Single Purpose）**：一篇文档只解决一个清晰主题/任务；当出现多个并列主题时，拆分为多篇，并在父文档提供索引。
- **务实为先（Practical First）**：以可执行的信息为中心，示例/步骤/决策理由优先，减少口号式描述。
- **结构可读（Readable Structure）**：优先三段式或总分总；段内列表短小精悍（3–7条）。
- **版本可追（Versioned）**：文首提供元信息；重大变更以“变更记录”列出。

## 2. 文档元信息

每篇文档开头必须包含以下信息（引用块书写）：

> 标题：{文档中文名}（{英文名可选}）  
> 适用范围：{读者与场景}  
> 目标：{一句话说明目标或关键产出}  
> 责任人：{Owner/Github ID}  
> 首次创建：YYYY-MM-DD  
> 最近更新：YYYY-MM-DD  
> 版本：vX.Y  

## 3. 命名与位置

- **文件命名**：`{序号}_{英文主题}_{中文标题}.md`
  - 例：`001_document-writing-standards_文档编写规范.md`
- **目录归属**：
  - 跨项目/统一标准 → `docs/shared/`
  - 某子项目专属 → `docs/projects/{project}/`
- **链接方式**：同仓库内使用相对路径；外部仓库使用明确的永久链接（tag/commit）。

## 4. 推荐结构

根据复杂度选择其一：

### 4.1 轻量文档（≤ 150 行）
1. 背景/目标（Why）
2. 操作/结论（What）
3. 步骤/示例（How）
4. 验收标准（Check）

### 4.2 标准文档（150–400 行，推荐）
1. 文档目标与范围  
2. 术语与前置条件  
3. 核心内容（分章节展开）  
4. 操作步骤/接口/模板  
5. 验收与度量  
6. 相关文档与参考

### 4.3 复杂主题（总分总）
- 总：问题定义/目标/范围/决策摘要
- 分：按模块/阶段分解（每节可单独阅读与执行）
- 总：关键结论/风险与边界/后续动作

## 5. 表达与格式

- **具体可执行**：避免“提高/加强/促进”等空词；使用量化或可验证的标准，例如“接口 p95 延迟 ≤ 300ms”。
- **术语一致**：首次出现的关键术语给出定义；多词术语可用 `/` 分隔（如 `学/练/测`）。
- **列表优先**：能列表不长段；一个列表不超过 7 条。
- **代码与配置**：使用带语言标识的代码块，给出最小可运行示例。
- **图表**：首选 Mermaid/表格，附上说明文字与数据来源。

## 6. 验收与检查清单（必填）

在文末添加如下检查清单，提交前自检：

- [ ] 单一主题且标题准确  
- [ ] 读者与适用场景明确  
- [ ] 关键结论清晰、可执行  
- [ ] 步骤/接口/示例齐全  
- [ ] 指向相关文档的链接有效  
- [ ] 元信息与更新时间已填写

- 指标口径：…

## 7. 自检清单

## 8. 何时拆分为多文档

- 同一文档出现 2 个及以上并列主题；
- 章节超过 6 个或长度 > 400 行且难以导航；
- 不同读者（教师/学生/运维）需要不同视角；
- 更新频率差异大导致相互影响。
